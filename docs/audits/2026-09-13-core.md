# Core audit — September 13, 2026

This first pass covers the root Rust package, concentrating on persistence,
market data, portfolio valuation/history, and sync recovery. It is not an
exhaustive audit of provider adapters, the HTTP server, credentials, or the UI.
Existing Schwab changes and unrelated local files were left in place.

## Highest-priority remaining work

### P1: Intraday history evaluates balances at the end of the day

**Confirmed by tracing the call path; no dedicated reproduction in this pass.**
[portfolio_history_scoped and portfolio_stacked_history](../../src/app/portfolio.rs)
accept full/hourly granularity, retain each change point's timestamp in the
output, but pass only `timestamp.date_naive()` into valuation.
[PortfolioService](../../src/portfolio/service.rs) then selects the last balance
on that date. A morning history point can therefore include an afternoon balance
change, and separate intraday points can show the same closing value.

**Next change:** add an explicit timestamp cutoff to the valuation API for
intraday queries while preserving end-of-day semantics for date queries. Specify
how observation timestamps interact with price dates, then test morning and
afternoon changes through both history outputs.

### P2: Sync cannot distinguish empty balances from unavailable balances

**Confirmed by inspection.** [SyncResult::save_with_clock](../../src/sync/mod.rs)
skips empty balance vectors. [Chase](../../src/sync/synchronizers/chase.rs) also
returns an empty vector when fetching an account's detail fails. Treating all
empty vectors as zero would clear legitimate holdings after transient errors;
skipping all of them cannot express a successful empty snapshot. Accounts absent
from a sync result are separately treated as inactive.

**Next change:** model balance retrieval as a successful complete snapshot or
an unavailable result, and make account-list completeness explicit before
deactivating missing accounts. Update adapters together with orchestration.

### P2: Feature declarations do not describe real module dependencies

**Reproduced.** `direnv exec . cargo test -p keepbook --lib --no-default-features`
fails: always-enabled models and storage import the feature-gated credentials
module. At audit time, storage tests also required the optional `tempfile`
dependency; the persistence follow-up makes that dependency unconditional for
atomic replacement. The credentials/module boundary is still broken.
By inspection, `app = []` and `portfolio = []` omit dependencies on other gated
modules; `app/preflight.rs` unconditionally imports git despite other app code
having a no-git fallback.

**Next change:** separate credential interfaces/configuration from optional
backends, declare actual feature dependencies, and test a supported feature
matrix. Keep test-only dependencies in dev-dependencies. Default/all-feature
builds alone cannot validate these boundaries.

### P2: History repeats storage scans and allocations for each sample

**Confirmed by inspection; not benchmarked.** Each history point invokes a new
valuation. That reloads account/connection maps, obtains complete balance logs,
and scans for the selected snapshot. Market-data queries obtain all observations,
clone cached yearly vectors, and sort the combined history. Asset breakdown also
separately loads balance history to derive freshness metadata.

The small selection-copy improvement below removes one redundant copy per
lookup; it does not resolve the larger repeated work.

**Next change:** prepare a request-scoped immutable history context once, with
sorted balance/price/FX data and indexed cutoff lookups. Avoid a global cache
without an invalidation contract. Benchmark representative account and history
sizes before changing concurrency or storage formats.

### P2: Some valuation failures become unexplained missing values

**Confirmed by inspection.** Several branches of
[PortfolioService::value_asset](../../src/portfolio/service.rs) turn any price/FX
error into an unavailable valuation. This includes storage/parse/provider errors,
not only absent observations. Summaries add available valuations, so operational
failures can yield a partial total without explaining why.

**Next change:** distinguish absent data from failed retrieval with typed outcomes,
and expose valuation completeness/diagnostics in the headless API. Preserve the
existing JSON contract or explicitly version/add fields with contract tests.

## Persistence follow-up

The original concurrency probe issued sixteen successful `put_prices` calls but
read back only one observation. This is now fixed by a shared file-persistence
primitive: stable cross-process writer locks, atomic replacements, coordinated
append readers, and blocking transactions that retain their locks on async
cancellation. Both storage adapters and their compaction/backfill paths use it.
Market-data writes bypass stale caches and invalidate cached results afterward.

The reproducer is now a normal regression in `tests/storage_concurrency.rs`,
alongside a multi-process test that concurrently writes prices, FX, registry
entries, transactions, and balances while another store reads and compacts.
[Persistence design and remaining limits](../storage-persistence.md) describe
crash recovery, external writers, and the per-file consistency boundary.

## Changes made in this pass

| Issue | Change | Regression coverage |
| --- | --- | --- |
| P1: Connection cursor persisted before data writes | Save connection state only after balances and transactions succeed; an ordinary write failure leaves the old cursor available for retry | Inject failures at balance and transaction paths, then repair and retry |
| P1: Raw/deserialized asset IDs escape the price directory | Validate every price path and validate the whole batch before any write | Reject absolute paths, traversal, empty/dot segments, backslashes, and NULs |
| P2: Fractional-second balances omitted at day end | Compare UTC dates in snapshot selection and freshness metadata | Include `23:59:59.999999999`, exclude next-day midnight, verify totals and freshness |
| P2: Older observations overwrite newer observations in memory | Keep the greatest observation timestamp for price/FX keys | Exercise out-of-order writes against both memory and JSONL stores |
| P2: FX future projection picks an older correction | On the earliest eligible date, select the latest observation timestamp | Bounded and unbounded projection with multiple observations and dates |
| Performance: whole histories cloned before selection | Borrow slices and clone only the selected observation | Existing selection tests plus the new store/projection regressions |

Cursor ordering improves recovery from reported write failures; it does not make
the multi-file sync atomic or guarantee durability after power loss. Partial
balance writes may be repeated on retry. Path validation is lexical and does not
provide containment against pre-existing symlinks in the data directory.

No CLI arguments, JSON field layouts, timestamp formatting, decimal formatting,
or persisted file formats were changed.

## Validation

The new market-data, portfolio, and sync-cursor regressions were observed failing
before their fixes. The first pass finished with 514 passing all-feature tests. After the persistence
follow-up, isolated all-feature validation passed **524 tests**, with five
existing live-provider tests ignored. Formatting, Clippy with warnings denied,
and the all-target/all-feature type check also passed.

Final validation commands, run through `direnv exec .`:

```sh
cargo test -p keepbook --all-targets --all-features --quiet
cargo clippy -p keepbook --all-targets --all-features -- -D warnings
cargo check -p keepbook --all-targets --all-features
cargo fmt -p keepbook --check
```

`git diff --check` also passed. The no-default-features failure remains tracked above. The concurrent-write
probe is now a passing regression. No Dioxus build or UI tests were run.

The environment also emitted a pre-existing `.envrc` nix-direnv hash mismatch
warning while continuing into the flake environment. This audit did not change
the environment configuration.
