# Core audit — September 13, 2026

This audit covers the root Rust package, concentrating on persistence, market
data, portfolio valuation/history, and sync recovery. It is not an exhaustive
audit of provider adapters, the HTTP server, credentials, or the UI. Existing
Schwab changes and unrelated local files were left in place.

The first pass fixed five data-handling bugs and the concurrent-write loss, and
left five priority findings with a "next change" each. The second pass made all
five, and a review pass checked them and corrected one; what follows describes
the second pass with the correction folded in, the review pass, then the first
pass's own changes.

## Second pass

Listed in the order the changes were made.

### P1: Intraday history evaluates balances at the end of the day

**Fixed.** `PortfolioQuery` now carries an optional `as_of_timestamp`. With one
set, only balances recorded at or before that instant count. Date queries pass
none and keep end-of-day semantics; so does sampled history, whose points are
dates rather than moments.

Price and FX observations carry the time keepbook recorded them, not a market
time: a date's close is usually written down that evening or backfilled days
later, and an earlier date's reading is settled however late it arrived. The
cutoff therefore only reorders readings dated its own day, preferring one
recorded by the cutoff over one recorded after it. Everything else selects as a
date query does. The review pass narrowed the rule to this: the first version
ranked every reading by whether it was recorded by the cutoff, which let a
weeks-old sync-time price beat a later-backfilled close for the point's own
date, the normal shape of a data directory that syncs Schwab and backfills
prices afterwards.

Regressions cover a morning and an afternoon balance change on one day, a
morning quote that must price a morning point ahead of that day's close, the
fallback when nothing had been recorded by the cutoff, and a backfilled close
that must beat an older recorded reading, through the service and
`portfolio history`.

### P2: Sync cannot distinguish empty balances from unavailable balances

**Fixed.** `AccountBalances` is either a `Snapshot`, which is always recorded
(an empty one means the account holds nothing), or `Unavailable`, which leaves
stored history untouched and is reported with its reason. Chase and Schwab
report unavailable where they previously returned an empty vector.

Account-list completeness is explicit as well: `AccountListing::Partial`
suppresses deactivating stored accounts missing from the result, since only a
complete listing proves an account is gone. Every adapter reports `Complete`
today; the type is what makes a partial listing expressible.

`sync` output gains `balances_unavailable` and `accounts_partial`, both omitted
when a sync was complete.

### P2: Feature declarations do not describe real module dependencies

**Fixed.** The credential interface, configuration, and non-age backends compile
unconditionally; only the age-encrypted backend, which needs the `age` crate,
stays behind the `credentials` feature. `app`, `portfolio`, `staleness`, and
`sync` declare the modules they import. `scripts/check-feature-matrix.sh` builds
every feature in isolation and runs in CI, since all-feature builds cannot catch
these gaps.

`tempfile` remains a normal dependency: atomic replacement uses it at runtime.

### P2: Some valuation failures become unexplained missing values

**Fixed.** Absent market data is now a typed `MarketDataMissing` error, so a
failed read is distinguishable from a price nobody has recorded. Portfolio
snapshots list the assets left out of `total_value` and why, asset breakdown
rows carry the same reason, and lookup failures are logged. A failed price-store
read is reported as an issue rather than aborting every other asset's valuation;
a malformed stored number still fails the command, which is loud by design.

The new fields are omitted when everything was valued, so existing output is
unchanged. `portfolio_snapshot_unpriced_asset` pins the new shape.

### P2: History repeats storage scans and allocations for each sample

**Fixed, and measured.** `PortfolioService::load_valuation_history` reads
accounts, connections, and balance logs once and sorts each account's snapshots;
each point searches that prefix and copies only the snapshot it selects.
Request-scoped read-through wrappers memoize storage and market data reads for
one history request and are dropped with it, so there is no cache to invalidate
across requests. Market data selection borrows a shared price history instead of
copying it.

`tests/portfolio_history_bench.rs` (ignored by default) times a representative
dataset: 20 accounts and 10 assets, 120 snapshots per account and 1000 daily
prices. In a debug build, 120 daily points went from 1.14s to 0.39s and 52
weekly points from 0.56s to 0.23s. Marginal cost per point fell from roughly
8.0ms to 1.1ms; the rest is the one-time load, which is why coarse granularities
move least. Storage formats and concurrency were left alone.

## Remaining work

- Change point collection, which reads every balance log and price history once,
  now dominates short histories. It is the next thing to measure.
- Price observations carry the time keepbook recorded them rather than a market
  time, so intraday accuracy is bounded by how often prices are written down. A
  separate market timestamp would let valuation order readings by when they were
  true.
- No adapter reports a partial account listing yet; the ones that fail to
  enumerate accounts still fail the whole sync.
- `asset_update_metadata` still reloads balance history per call. It runs once
  per `portfolio assets` request rather than per history point, so it was left
  out of this pass.

## Persistence follow-up

The original concurrency probe issued sixteen successful `put_prices` calls but
read back only one observation. This is now fixed by a shared file-persistence
primitive: stable cross-process writer locks, atomic replacements, coordinated
append readers, and blocking transactions that retain their locks on async
cancellation. Both storage adapters and their compaction/backfill paths use it.
Market-data writes bypass stale caches and invalidate cached results afterward.

The reproducer is now a normal regression in `tests/storage_concurrency.rs`,
alongside a multi-process test that concurrently writes prices, FX, registry
entries, transactions, and balances while another store reads and compacts.
[Persistence design and remaining limits](../storage-persistence.md) describe
crash recovery, external writers, and the per-file consistency boundary.

## Changes made in this pass

| Issue | Change | Regression coverage |
| --- | --- | --- |
| P1: Connection cursor persisted before data writes | Save connection state only after balances and transactions succeed; an ordinary write failure leaves the old cursor available for retry | Inject failures at balance and transaction paths, then repair and retry |
| P1: Raw/deserialized asset IDs escape the price directory | Validate every price path and validate the whole batch before any write | Reject absolute paths, traversal, empty/dot segments, backslashes, and NULs |
| P2: Fractional-second balances omitted at day end | Compare UTC dates in snapshot selection and freshness metadata | Include `23:59:59.999999999`, exclude next-day midnight, verify totals and freshness |
| P2: Older observations overwrite newer observations in memory | Keep the greatest observation timestamp for price/FX keys | Exercise out-of-order writes against both memory and JSONL stores |
| P2: FX future projection picks an older correction | On the earliest eligible date, select the latest observation timestamp | Bounded and unbounded projection with multiple observations and dates |
| Performance: whole histories cloned before selection | Borrow slices and clone only the selected observation | Existing selection tests plus the new store/projection regressions |

Cursor ordering improves recovery from reported write failures; it does not make
the multi-file sync atomic or guarantee durability after power loss. Partial
balance writes may be repeated on retry. Path validation is lexical and does not
provide containment against pre-existing symlinks in the data directory.

No CLI arguments, JSON field layouts, timestamp formatting, decimal formatting,
or persisted file formats were changed.
